# Plan

Make the Vercel deployment work without relying on a private backend service credential, and keep inventory data shared across browsers.

## What will change

1. Add secure database-side operations for the HPT app:
   - employee/admin login lookup
   - component search, create, update, delete
   - employee management
   - admin inventory statistics

2. Update the app server data layer to call those database operations using the public backend key that Vercel can safely receive as an environment variable.

3. Keep the existing HTTP-only signed cookie session flow so each browser signs in securely while all saved component/user data remains centralized and visible from any browser after login.

4. Update Vercel deployment docs so the required variables are clear:
   - `SUPABASE_URL` or `VITE_SUPABASE_URL`
   - `SUPABASE_PUBLISHABLE_KEY` or `VITE_SUPABASE_PUBLISHABLE_KEY`
   - `HPT_SESSION_SECRET`
   - no private service credential required for this HPT app path after the migration is applied

5. Verify the login/dashboard flow locally and check current build diagnostics.

## MongoDB answer

MongoDB can be used, but I do not recommend switching for this issue. It would require replacing the current database schema, server functions, employee management, and deployment configuration, and Vercel would still need a `MONGODB_URI` secret. The faster and safer fix is to keep the current hosted database and remove the Vercel dependency on the missing private credential.

## Technical details

- Add a new SQL migration with `SECURITY DEFINER` RPC functions and explicit grants.
- Grant only function execution to `anon`/`authenticated`; keep direct table access locked behind RLS.
- Preserve PBKDF2 password verification in app code for login so password hashes are never exposed to the browser.
- Create a server-side public backend client inside the server-only data helper using environment fallbacks.
- Do not store secrets in code. Vercel still needs `HPT_SESSION_SECRET` set as a stable random value for cookies.
